# 프로젝트 지침과 문서 구성

여러 프로젝트에서 공통 원칙과 프로젝트 지식을 중복 없이 관리하기 위한 권장 구조다.
기존 프로젝트의 구조와 도구가 요구하는 위치를 우선한다. 구조를 맞추기 위한 파일 이동이나 문서 생성은 하지 않는다.

## 정보의 소유 위치

| 정보 | 원본 위치 |
| --- | --- |
| 개인 공통 규칙·작업 절차·설계 기준 | 이 워크플로우 저장소 |
| 프로젝트 명령·규칙·아키텍처·업무 지식 | 해당 프로젝트 |
| 모델·권한·훅·도구 전용 기능 | 도구별 설정 또는 연결부 |
| 임시 계획·검증 결과·세션 기록 | 프로젝트 관례에 따른 문서 또는 로컬 작업 공간 |

프로젝트 문서에 공통 규칙 전체를 수동 복사해 별도로 관리하지 않는다. 도구용 생성 파일은 원본과 생성 경로를 명시하고 직접 편집하지 않는다.

## 신규 프로젝트 권장 구조

필요한 문서만 만든다. 아래 이름은 예시이며 기존 동등 문서가 있으면 사용한다.

```text
AGENTS.md              프로젝트의 공통 지침 원본
README.md              프로젝트 소개·설치·실행
CONTEXT.md             중요한 도메인 용어·관계·불변식
docs/
  specs/               기능 목표·범위·수용 기준
  adr/                 중요한 설계 결정과 이유
  tasks/               실행 단위와 검증 상태(필요한 경우)
```

도구별 진입 파일은 해당 도구가 요구하는 위치에 두고 프로젝트 공통 원본을 참조하거나 생성한다.
특정 도구의 진입 파일을 전체 문서의 대표 원본으로 삼지 않는다. 숨김 디렉터리도 도구가 요구하면 사용한다.

## 프로젝트 지침에 담을 내용

- 프로젝트 목적과 핵심 디렉터리
- 실제 설치·실행·테스트·타입 검사·빌드 명령
- 공통 기본값과 다른 프로젝트 관례
- 변경 시 지켜야 할 계약과 알려진 제약
- 상황별로 읽을 도메인·스펙·설계 문서의 위치

항상 읽는 지침은 핵심으로 유지하고 상세 설명은 조건과 링크로 연결한다.
링크만 나열하지 말고 언제 읽을지 명시한다. 경로 변경 시 참조와 생성 결과도 확인한다.
개인 비밀값·세션 인증 정보·로컬 실행 산출물은 공유 지침에 넣지 않는다.

## 유지 관리

작업 중 중요한 도메인·설계 결정이 바뀌면 해당 원본을 갱신한다.
규칙이 충돌하면 프로젝트의 구체적인 작업 규칙을 공통 기본값보다 우선하며, 도구의 권한 제한을 문서로 우회하지 않는다.
반복되는 지침은 소유 문서 한 곳에 두고 다른 문서에서는 연결한다. 오래된 규칙은 근거를 확인한 뒤 수정한다.
