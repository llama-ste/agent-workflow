# 맥락정리와 인계

사용자가 맥락정리 또는 인계를 요청하면 다른 세션·모델·사람이 작업을 이어갈 수 있도록 현재 상태를 정리한다.
대화의 시간순 요약보다 남은 작업을 정확하게 재개하는 데 필요한 정보를 우선한다.

모델·세션 교체를 위한 인계는 새 세션이 읽을 수 있어야 하므로 기본적으로 파일로 남긴다. 저장 위치는 프로젝트 문서 관례를 따르고, 없으면 `.claude/handoff.md`를 사용한다. 저장 후 경로를 알린다.

## 1. 실제 상태 확인

- 원래 목표, 이후 수정된 요구사항, 제외한 범위, 사용자 제약을 확인한다.
- Git 저장소라면 현재 브랜치, `git status --short`, 필요한 diff를 확인한다. 미추적 파일과 staged 변경도 포함한다.
- 사용자의 기존 변경과 이번 작업의 변경을 구분한다. 구분할 근거가 없으면 불명확하다고 쓴다.
- 실행한 검증 명령과 결과를 확인한다. 검증 이후 코드를 바꿨다면 이전 통과 결과가 현재 상태를 보장하지 않음을 밝힌다.
- 실행 중인 작업이나 임시 작업 사본이 있다면 위치·상태·목적을 기록한다. 확인하지 않은 프로세스를 실행 중이라고 단정하지 않는다.
- Git을 사용하지 않는 작업이라면 관련 파일과 결과물을 기준으로 확인한다.

## 2. 인계 내용

다음 형식을 기본으로 사용한다. 단순한 작업은 각 항목을 1~3줄로 줄이되 재개에 필요한 경로·명령·조건은 남긴다.

```text
목표와 범위
- 최종 목표, 성공 기준, 중요한 제약과 비목표

현재 상태
- 완료 / 진행 중 / 미착수 작업
- 작업 위치와 브랜치, 미커밋 변경 여부

핵심 결정과 이유
- 선택한 접근법과 이유
- 진행에 영향을 주는 가정, 사용자가 확정한 사항과 미결정 사항

변경 파일과 결과물
- 경로별 변경 요지와 읽어야 할 핵심 위치
- 사용자 변경과 주의해서 보존할 내용

검증 상태
- 실행 명령, 결과, 검증한 시점의 코드 상태
- 미실행 항목과 사유, 알려진 실패와 재현 조건

다음 작업
- 바로 수행할 첫 행동과 완료 확인 방법
- 이후 남은 순서, 장애 요인과 필요한 사용자 답변
```

## 3. 정확성과 범위

- 확정 사실, 추정, 제안을 구분한다. 기존 사용자 승인의 범위를 확대해서 전달하지 않는다.
- 실패한 접근법은 같은 실수를 반복할 가능성이 있을 때만 원인과 함께 기록한다.
- '테스트 완료', '거의 끝남' 같은 모호한 표현 대신 검증 명령과 남은 작업을 적는다.
- 민감한 값은 포함하지 않는다. 환경 정보가 필요하면 변수 이름과 설정 위치만 기록한다.
- 인계 요청만으로 새 구현, 커밋, 프로세스 종료를 시작하지 않는다.
- 기본 결과는 대화에 제공한다. 모델·세션 교체용 인계이거나 파일 저장 요청이 있으면 프로젝트 문서 관례(없으면 `.claude/handoff.md`)에 저장하고 경로를 알린다.
