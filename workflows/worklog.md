# 작업 기록과 의사결정 로그

한 작업의 **의사결정 서사**를 남긴다. 느낀 점 회고가 아니라, "무슨 문제로 시작 → 어떤 방향들이 있었나 → 트레이드오프를 어떻게 저울질해 무엇을 결정 → 결과"를 기록한다.
연말 성과 정리와 포트폴리오에서 판단 근거를 그대로 꺼내 쓰는 것이 목적이다.

## 언제 남기나

- 사용자가 "작업 기록 남겨줘", "worklog 남겨줘" 등으로 요청하면 실행한다.
- 의미 있는 작업을 마쳤거나 PR·인계 등 자연스러운 종료 지점에서는 기록을 남길지 **한 번 가볍게 제안**할 수 있다. 제안은 실행이 아니며, 사용자가 동의할 때만 기록한다.
- 자동으로 기록하지 않는다. 요청이나 동의가 없으면 기록하지 않고, 같은 작업에 반복해서 다시 권하지 않는다.
- 기록은 별도 구현·커밋·전송을 유발하지 않는다. 기본 결과는 로컬 파일 생성까지다.

## 무엇을 기록하나

먼저 이번 작업의 실제 내용을 확인한다. 대화의 목표·변경·검증 결과와 Git 상태(브랜치, `git status --short`, 관련 diff, PR·커밋 링크)를 근거로 삼는다.
확정 사실과 추정을 구분하고, 근거 없는 판단 서사를 지어내지 않는다.

한 기록은 **하나의 의사결정 단위**를 다룬다. 한 세션에서 성격이 다른 작업을 여러 건 했다면 기록을 나눈다.
제목에 "그리고"로 두 주제가 묶이거나, `type`이나 `outcome`이 사안마다 달라지면 나눠야 한다는 신호다.

## 기록 형식

기록은 작업 저장소가 아니라 **중앙 보관소(vault)** 한 곳에 모은다. 위치는 `WORKLOG_VAULT` 환경변수가 가리키는 디렉터리이며, 셸에 없으면 `source ~/.config/agent-workflow/env`로 읽는다.

```
$WORKLOG_VAULT/<연도>/<날짜>-<슬러그>.md
```

예: `$WORKLOG_VAULT/2026/2026-09-17-discount-calc-decision.md`.
같은 경로가 이미 있으면 덮어쓰지 않고 슬러그를 조정한다. 작업 저장소에는 기록을 남기지 않는다.

```markdown
---
date: 2026-09-17
project: <저장소/제품 이름>
title: <한 줄 제목>
type: feature            # feature | bugfix | refactor | decision | ops | review
scope: <도메인 예: 결제/할인>
decision: <한 줄 결론 — 연말·포트폴리오 스캔용>
outcome: 완료             # 완료 | 진행중 | 보류
links: [PR/이슈/커밋 URL]
---

## 배경 — 무슨 문제로 시작했나
## 검토한 방향 — 어떤 선택지가 있었나
## 트레이드오프와 결정 — 무엇을 왜 골랐나
## 결과 — 실제로 어떻게 됐나
## 남은 것 (선택)
```

- 프론트매터는 나중에 집계·검색·외부 서비스 속성 매핑에 쓰인다. 필드를 임의로 늘리지 말고 필요하면 먼저 제안한다.
- 본문의 핵심은 "트레이드오프와 결정" 섹션이다. 고른 선택지뿐 아니라 **버린 선택지와 이유**를 함께 남긴다.
- 관련된 과거 기록이 있으면 `[[<날짜>-<슬러그>]]` 형식으로 연결한다. 같은 주제의 결정이 이어질 때 맥락이 유지된다.
- 기록은 판단의 서사이지 작업 보고서가 아니다. 나중에 훑어 읽을 분량(**대략 60줄 이내**)을 넘기지 않는다.
- "남은 것"은 짧은 목록으로 유지한다. 자체적인 검토와 결정이 필요한 후속 과제는 여기에 길게 적지 말고 별도 기록으로 분리한다.
- 민감한 값(키·토큰·인증 정보·개인정보)은 기록하지 않는다. 필요하면 위치와 변수 이름만 남긴다.

## 과거 기록 참조

기록이 한 곳에 모이므로, 작업 중에 과거의 판단을 근거로 쓸 수 있다. 같은 도메인이나 비슷한 결정을 다룰 때 먼저 확인한다.

```sh
# 도메인·유형으로 좁히기 (프론트매터 필터)
grep -rl 'scope: 결제' "$WORKLOG_VAULT" | xargs grep -l 'type: decision'

# 주제어로 찾기
grep -rli '<검색어>' "$WORKLOG_VAULT"
```

찾은 기록의 "트레이드오프와 결정"을 읽고, 이미 검토해 버린 선택지를 다시 제안하지 않는다.
과거 결정과 다른 선택을 하려면 무엇이 달라졌는지 밝힌다. 참조한 기록은 새 기록에서 `[[...]]`로 연결한다.
보관소에 접근할 수 없으면 그 사실을 보고하고, 없는 기록을 추측으로 지어내지 않는다.

## 이미지와 시각 자료

글만 있는 기록은 나중에 다시 읽히지 않는다. 판단과 결과를 빠르게 보여주는 시각 자료를 함께 남긴다.

- 화면 변화는 전/후 스크린샷, 구조·흐름은 다이어그램, 수치는 그래프로 남긴다.
- 이미지 파일은 `$WORKLOG_VAULT/assets/<슬러그>/`에 두고, 본문에서 상대 경로(`![설명](../assets/<슬러그>/파일)`)로 참조한다.
- 앱을 로컬에서 실행할 수 있으면 브라우저 도구로 직접 캡처한다. 실행·로그인·테스트 데이터 준비가 필요하면 사용자에게 요청한다.
- 전/후 비교가 필요하면 **수정 전에 미리 캡처**한다. 고친 뒤에는 이전 상태로 되돌려야 찍을 수 있다.
- 캡처는 **로컬 개발 환경에서만** 한다. 운영 화면은 찍지 않는다.
- 캡처 전에 화면에 실제 고객 데이터·내부 URL·개인정보가 있는지 확인한다. 있으면 가리거나 촬영하지 않는다.
- 캡처한 이미지는 기록에 넣기 전에 무엇을 찍었는지 알리고 확인받는다.
- 이 마크다운 원본은 Notion·블로그·HTML 등에서 이미지와 서식이 그대로 보기 좋게 렌더링된다. 캡처 단계의 목적은 표현 재료(스크린샷·다이어그램·결론 한 줄)를 잘 남기는 것이다.

## 중앙 보관과 전달 (선택)

보관소(`$WORKLOG_VAULT`)의 마크다운이 **유일한 원본**이다. Notion과 HTML은 여기서 파생되는 표현이며, 원본을 대체하지 않는다.
Notion은 집계·열람, HTML은 시각화를 맡는다. 연결이 없어도 보관소의 기록은 그대로 동작한다.
보관소는 Obsidian으로 열면 링크·백링크·그래프로 탐색할 수 있다. 앱 없이도 일반 마크다운 폴더로 동작한다.

전송은 **사용자가 요청하거나 동의했을 때만** 실행한다. 외부 서비스로 내보내는 작업이므로 임의로 수행하지 않는다.
아래 `scripts/` 경로는 **이 문서가 속한 워크플로우 저장소** 기준이다. 이 문서를 읽은 절대 경로에서 저장소 루트를 구해 사용한다.

```sh
# Notion 동기화 (HTML 첨부 포함)
python3 <워크플로우 저장소>/scripts/sync_notion.py <기록.md> --with-html

# HTML만 생성 (포트폴리오·블로그용 단일 파일)
python3 <워크플로우 저장소>/scripts/render_worklog.py <기록.md> -o <출력.html> --embed
```

`NOTION_TOKEN`·`NOTION_DB_ID`가 셸 환경에 없으면 `source ~/.config/agent-workflow/env &&`를 명령 앞에 붙인다.
토큰 값은 출력하거나 기록에 남기지 않는다. 같은 제목이 이미 있으면 새로 만들지 않고 갱신된다.

사적인 기록은 공개 저장소에 커밋하지 않는다. 공개 대상 저장소에서는 기록 위치를 버전 관리에서 제외하거나 중앙 저장소로만 보관한다.
